# Legacy → New Mapping

| Legacy capability | Legacy source | Business purpose | Verdict | New capability | Notes |
|---|---|---|---|---|---|
| Admin login + role-based redirect | `application/core/MY_Controller.php`, `application/helpers/function_helper.php` (`is_adminprotected`, `validate_admin_login`) | authenticate staff/customers | SIMPLIFY | `/auth/login` + JWT/session, two-role check | drop the 5-way user_type redirect logic, keep the concept |
| MD5 password hash + `pwdstring` plaintext-like column | `panacea.sql` `users` | store credentials | **DROP** | bcrypt/argon2 password hash only | security smell, no legitimate reason to retain |
| `certificate_key`/`new_certificate_key`/`is_certificate_verified` device gate | `panacea.sql` `users` | unclear device/cookie trust mechanism | **DROP** | standard session/JWT expiry + optional "remember me" cookie | unconfirmed purpose, clear smell (opaque secret in plaintext DB column) |
| `ID_encode`/`ID_decode` URL obfuscation | `application/helpers/function_helper.php` | hide numeric IDs in URLs | **DROP** | real authorization checks (scoping middleware) | trivially reversible, provides no actual security |
| `roles` table (Administrator/Employee/Supplier/Sub-contractors) | `panacea.sql`, `admin/controllers/Role.php` | generic role management | **DROP** | fixed 2-value `users.role` enum | disconnected from actual `user_type` persona system in use |
| `cms` module (add/edit/listing/view) | `admin/controllers/Cms.php` + views | static page content management | **DROP** | none — out of scope | no observed connection to compliance domain, likely boilerplate |
| `archive` module | `admin/controllers/Archive.php` + view | unclear (possibly soft-delete/audit view) | **DROP** (pending confirmation) | none in V1 | purpose unconfirmed; revisit if a real audit-log requirement surfaces |
| `country` reference table | `panacea.sql` | address/locale dropdown | **DROP** | none in V1 | no confirmed workflow requires country selection |
| `services` (PCI DSS/ISO/HIPAA/HITRUST) + `testing` (ASV/PT/VA/...) as two parallel concepts | `panacea.sql` `services`, `testing`; `admin/controllers/Testing.php` | define the framework/type being assessed | SIMPLIFY | `checklistTemplates.category` (free text) | one generic template concept replaces two parallel entity types |
| `compliance_project` | `panacea.sql`, `admin/controllers/Compliances.php` | one compliance engagement (customer × service × review team) | KEEP concept / REPLACE shape | `assessments` collection | drop process indirection and 3-reviewer assignment; single auditor |
| `testing_project` | `panacea.sql`, `admin/controllers/Testing.php` | one testing engagement, structurally duplicate of compliance_project | **DROP as separate entity** | merged into `assessments` | near-total duplication of Compliances; no reason to keep two code paths |
| `process` (named container per customer) | `panacea.sql` | scope/grouping label for engagements | **DROP** (fold into assessment) | optional `assessments.scopeNote` string | business value of a separate Process entity unconfirmed from code alone |
| `questionnaire` (flat question list per service, edit+toggle only) | `panacea.sql`, `admin/controllers/Questionnaire.php` | the question bank | REPLACE | `checklistTemplates.sections[].questions[]` | adds real authoring: create, section, reorder, mandatory/optional, guidance, expected evidence — none existed in legacy |
| `uplaod_evidence` (per-question status + single evidence file) | inferred from `application/helpers/function_helper.php`, `admin/controllers/Compliances.php` | the response + review-state fact table | KEEP concept / REPLACE shape | `assessmentResponses` + `evidence` (split) | separates answer/status from evidence and comments instead of one overloaded row |
| `common_uplaod_docs` | inferred from `function_helper.php` (`get_common_docs`, `get_qsa_document`) | secondary/multi-file evidence store, overlapping with `uplaod_evidence.docs` | **DROP as separate table** | folded into `evidence` collection (supports many files per response natively) | ambiguous legacy split resolved by one clean multi-file model |
| `all_comments` / `qsa_comments` / `qa_comments` / `consultant_comments` (4 parallel tables) | inferred from `function_helper.php` | per-role comment threads | **DROP as 4 tables** | single `comments` collection, tagged by authorRole | biggest single simplification: one thread, not four siloed ones |
| `admin_status_log` | inferred from `function_helper.php::admin_log` | status change history log | **DROP for V1** | `assessmentResponses.reviewedAt/reviewedBy` (single latest state only) | full history/audit trail is a good Session-5-style hardening add-on, not MVP-critical |
| `accepttocustomer` / `accepttoqsa` / `accepttoqa` / `AcceptToConsultant` (4 separate accept actions) | `admin/controllers/Compliances.php` | per-role approval of a customer's modification/resubmission | SIMPLIFY | single `POST .../responses/:id/review` with `decision` | one auditor role needs one accept action, not four role-scoped ones |
| `select_multiple_change_status` (bulk Approve/Disapprove/Mark Incomplete, all_status 7/8/9) | `admin/controllers/Compliances.php` | bulk review action across selected questions | KEEP concept / SIMPLIFY | question status enum (`accepted`/`non_compliant`/`needs_clarification`) + optional bulk-accept in UI | same three outcomes, cleaner naming, no magic numbers |
| `EndDateformAdmin` | `admin/controllers/Compliances.php` | manually set engagement end date | KEEP | `assessments.dueDate` PATCH | trivial field edit, no change needed |
| `FileUploadAOC` / `FileUploadROC` (one-shot report upload) | `admin/controllers/Compliances.php` | attach final compliance report | SIMPLIFY | `evidenceReports` collection, versioned | legacy rigidly rejects re-upload; new design allows versioned replace |
| Consultant / QA / QSA modules + views (3 near-identical reviewer personas) | `application/modules/consultant`, `qa`, `qsa` | three separate reviewer roles reviewing the same question list | **DROP as separate roles** | single `Auditor` role | screens were near-duplicates of each other and of Admin's review screen; no distinct business capability confirmed per role beyond the accept-handler split above |
| Customer `Attestaions` module (dashboard/details/report) | `customer/controllers/Attestaions.php` + views | final attestation sign-off/report viewing | SIMPLIFY | folded into Assessment Overview (COMPLETED state) + `/assessments/:id/report` download | a distinct module wasn't justified by confirmed unique behaviour beyond "view/download the final report" |
| Profile / Reset Password (duplicated across 5 modules) | `admin`, `consultant`, `customer`, `qa`, `qsa` — all have identical `profile/profile.php` + `profile/reset_password.php` | self-service account management | SIMPLIFY | one shared Account Settings screen | pure implementation duplication, zero variation found |
| Customer sub-accounts (`users.parent_id`) | `panacea.sql`, `function_helper.php` (`common_function`, `customer_comments`, etc. all walk parent_id) | multiple named users under one client company | KEEP concept / SIMPLIFY | flat `organisationId` membership on `users` | same business outcome (multiple people per customer org) without a recursive parent/child user tree |
| PHPExcel / mpdf usage (export, PDF generation) | `application/libraries/*`, referenced by admin module | export question/response lists, generate report PDFs | KEEP (as capability, not code) | server-side CSV/PDF export endpoint, implementation TBD | vendor library internals out of scope per task instructions; only the capability itself survives |
